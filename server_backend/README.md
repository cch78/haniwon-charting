# 한의원 차팅 – 서버 백엔드 이전 계획 (미착수)

> 이 폴더는 **한의맥 서버 PC(192.168.0.226)에서 상주 실행할 중계 백엔드**를 위한 것입니다.
> 아직 코드는 없고, 착수 시 이 문서의 "명령문"을 그대로 세션에 붙여넣어 시작합니다.

---

## 왜 (배경)

현재 구조:
- 크롬 확장(newtab.js)과 모바일 웹(mobile/)이 **각 클라이언트에서 직접**
  한의맥 API·Claude API·구글 시트를 호출.
- 문제점:
  - Claude API 키가 PC/기기마다 저장됨 (유출 위험, 관리 분산)
  - 모바일은 별도 정적 서버(serve_mobile.ps1)를 또 띄워야 함
  - 캐싱·재시도·로깅이 클라이언트마다 제각각

목표 구조:
- 서버 PC(226)에 **경량 백엔드 1개**를 상주시켜 아래를 중계:
  - 한의맥 조회/저장 (`192.168.0.226:6982`, 이미 로컬)
  - Claude API 호출 (키는 **서버에만** 보관)
  - 구글 시트 저장/조회
  - 모바일 정적 페이지 서빙도 겸함 (serve_mobile.ps1 대체)
- 클라이언트(확장·모바일)는 **서버 한 곳(`http://192.168.0.226:PORT`)** 만 바라봄.
- 이점: 키 일원화, 캐시·로깅·에러복구 단일화, 신규 클라이언트도 같은 백엔드 공유.

---

## 무엇을 (범위)

1. **백엔드 서버** (서버 PC 상주)
   - 스택 후보: Node(Express) 또는 Python(FastAPI). 226 PC 환경 확인 후 결정.
   - 엔드포인트(안):
     - `GET  /api/today` → 오늘 환자 (한의맥 waitpat 중계)
     - `POST /api/analyze` → 메모 → Claude 차팅 (서버가 키 보유)
     - `POST /api/guide` → 복약지도문 생성
     - `POST /api/save/hanymac` → 한의맥 저장 중계
     - `POST /api/save/sheet` · `GET /api/sheet` → 구글 시트 중계
   - 정적 서빙: `/` → 모바일 페이지
   - 설정: `.env` (Claude 키, 구글시트 URL, 한의맥 주소) — **git에 올리지 말 것**
   - 상시 실행: Windows 서비스 등록 또는 시작 프로그램 등록 스크립트

2. **클라이언트 개편**
   - 모바일(mobile/app.js): 직접 호출 → 백엔드 호출로 교체, 키 입력 UI 제거
   - 확장(newtab.js): 백엔드 경유 모드 추가 (기존 직접호출 모드는 fallback 유지 검토)

3. **마이그레이션**
   - 기존 구글 시트 스키마·Apps Script 그대로 재사용
   - 확장 자동업데이트(update.ps1)와 공존/대체 방식 결정

---

## 주의 (반드시 유지)

- 클라이언트가 HTTPS면 `http://226` 혼합콘텐츠 차단 → 백엔드는 **평문 HTTP, 원내망 전용**.
- 원내망(192.168.0.x)에서만 동작 (한의맥이 내부망 전용).
- API 키는 서버 `.env`에만. 클라이언트·git에 절대 넣지 말 것.
- 기존 확장 기능은 개편 완료·검증 전까지 **건드리지 말 것** (별도 브랜치/폴더에서 작업).

## 참고 (현재 파악된 사실)

- 한의맥 서버 `192.168.0.226:6982`, 인증 대부분 불필요, **CORS `*` 허용** → 브라우저 직접호출 가능.
- 주요 API: `/api/patinfo/waitpat?date=YYYY-MM-DD`(오늘 환자),
  `/api/treat/record`(POST 저장, `{JSONdata:{증상,챠트번호,진료일자,진료번호}}`).
- 구글 시트: Apps Script exec URL, action `saveRecord`/`getRecords`, 스키마는 apps_script_Code.gs.
- 모바일 현재 구조: mobile/index.html + app.js + serve_mobile.ps1 (정적 서버).
